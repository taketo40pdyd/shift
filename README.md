# シフト管理

スタッフのシフト作成・希望収集・人員不足チェック・給与目安の計算・PDF/CSV/ICS 出力までできるシフト管理アプリです。
ブラウザだけで動き、ホーム画面に追加（PWA）するとオフラインでも使えます。

## ファイル構成

```
/（すべて同じ階層に置きます。フォルダはありません）
├─ index.html              アプリ本体
├─ manifest.webmanifest    PWA の設定（名前・アイコン・ショートカット）
├─ sw.js                   Service Worker（オフライン対応・更新のお知らせ）
├─ .nojekyll               GitHub Pages にファイルをそのまま配信させるための空ファイル
├─ icon-192.png / icon-512.png                  アプリアイコン
├─ icon-maskable-192.png / icon-maskable-512.png  Android 用アイコン
├─ apple-touch-icon.png / favicon-32.png        iPhone 用・タブ用アイコン
├─ screenshot-wide.png / screenshot-narrow.png / screenshot-portal.png  インストール画面の画像
└─ firestore.rules         Firestore のセキュリティルール（Firebase コンソールに貼り付けて使う）
```
## GitHub Pages で公開する

1. GitHub で新しいリポジトリを作成します（無料プランでは **Public** にする必要があります）。
2. このフォルダの中身を、リポジトリの **いちばん上の階層** にアップロードします。
   - ブラウザからなら「Add file → Upload files」にフォルダの中身をまとめてドラッグ＆ドロップします。
   - `.nojekyll` は隠しファイルなので、ドラッグで入らないことがあります。その場合は「Add file → Create new file」でファイル名を `.nojekyll` にして、中身は空のまま保存してください。
3. リポジトリの **Settings → Pages** を開き、次のように設定して Save します。
   - Source: **Deploy from a branch**
   - Branch: **main** / **(root)**
4. 1〜2分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けるようになります。

## Firebase の設定（ログイン・クラウド同期・共有リンク）

公開したドメインでログインできるように、次の2つを設定します。

1. **Firebase コンソール → Authentication → 設定 → 承認済みドメイン** に `<ユーザー名>.github.io` を追加
2. **Authentication → Sign-in method** で「Google」「メール/パスワード」「匿名」を有効化

おすすめ（任意）：Google Cloud コンソール → APIとサービス → 認証情報 で、Firebase の API キーに
HTTP リファラーの制限（`https://<ユーザー名>.github.io/*`）をかけておくと、他のサイトで使われにくくなります。

### Firestore（クラウド同期・スタッフ用共有リンクに必要）

1. **Firestore Database → データベースを作成** を押し、「本番環境モード」で作成します（ロケーションは `asia-northeast1`（東京）がおすすめ）。
2. **Firestore Database → ルール** に `firestore.rules` の内容をすべて貼り付けて **公開** します。
   ルールを公開しないと、同期も共有リンクも「アクセスが許可されていません」になります。
3. ルールを更新したときも、同じ手順で貼り付けて公開し直してください。

## 主な機能

- **クラウド同期**：ログインすると、データが自動でクラウドに保存され、同じアカウントでログインした別の端末にすぐ反映されます。
  状態は画面上部の雲のアイコン、または「設定 → クラウド同期」で確認できます。
  同じ拠点を2台で同時に編集した場合は、片方を「〇〇（この端末の変更）」という別の拠点として残します（どちらの変更も消えません）。
- **スタッフ用の共有リンク**：「スタッフ」タブ → 各行の「⋮」→「共有リンクを作成」。
  スタッフはログインなしで自分のシフトを確認し、希望シフトを提出できます。提出された希望はシフト表の「希望」に自動で入ります。
- **バックアップファイルを直接開く**：Android の共有メニューからアプリに送る、パソコンでインストールしたアプリで .json を開く、画面にドラッグ＆ドロップ、のいずれかで読み込めます。
- **インストール**：Chrome / Android ではスクリーンショット付きのインストール画面が出ます。iPhone では画面内で追加方法を案内します。

## 更新するとき

- `index.html` を差し替えてコミットするだけで反映されます。開いている人の画面には「新しいバージョンがあります」と表示されます。
- `sw.js` を書き換えたときは、ファイル先頭の `VERSION` も変更してください（古いキャッシュが消えます）。
- GitHub Pages はファイルを最大10分ほどキャッシュするため、反映まで少し時間がかかることがあります。

## 注意

- シフトなどのデータは、各端末のブラウザ内（localStorage）に保存されます。端末を変えるときは「バックアップ」から書き出して読み込んでください。
- GitHub Pages で公開した場合、Google ログインはポップアップ方式で動きます。
  ホーム画面に追加したアプリ（特に iPhone）ではリダイレクト方式になり、ブラウザの設定によってはログインが完了しないことがあります。
  その場合はメールアドレスでのログインを使うか、Firebase Hosting での公開を検討してください。
